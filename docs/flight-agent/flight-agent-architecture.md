# Flight Agent 架构设计文档

## 1. 概述

Flight Agent 是 AI Travel Assistant 系统中的核心模块之一，负责处理用户的航班查询与预订相关的所有交互。本模块采用 ReAct (Reasoning + Acting) Agent 架构，通过多轮对话引导用户完成航班搜索流程。

## 2. 核心目标

- 提供自然、流畅的多轮对话体验
- 准确识别用户的出发地、目的地、日期等关键信息
- 通过 SerpAPI Google Flights Autocomplete API 辅助用户选择机场
- 收集完整参数后调用航班搜索 API 返回结果

## 4. 模块职责

### 4.1 Flight ReAct Agent
- **职责**：作为核心协调者，决定何时提问、何时调用工具、何时展示结果
- **输入**：用户自然语言消息
- **输出**：Agent 响应（问题/结果/澄清请求）

### 4.2 Tool: Google Flights Autocomplete
- **职责**：根据用户输入的城市名/关键词，返回匹配的机场列表
- **触发条件**：用户提供出发地或目的地但未指定具体机场
- **API**：`google_flights_autocomplete` (SerpAPI)

### 4.3 Tool: Google Flights Search (后续实现)
- **职责**：根据完整参数（出发机场、到达机场、日期等）搜索航班
- **触发条件**：所有必要参数收集完毕且用户确认
- **API**：`google_flights` (SerpAPI)

### 4.4 Memory Module
- **职责**：存储对话上下文、已收集的参数、用户选择
- **存储内容**：
  - 出发机场 (departure_airport_id)
  - 到达机场 (arrival_airport_id)
  - 出发日期
  - 返回日期（往返时）
  - 乘客人数
  - 舱位偏好

## 5. Agent 状态流转

```
[初始状态]
     │
     ▼
[收集出发地] ──用户提供城市名──► [调用Autocomplete] ──► [展示机场列表等待选择]
     │                                              │
     │                                              ▼
     │                                        [用户确认机场ID]
     │                                              │
     ▼                                              │
[收集目的地] ◄──────────────────────────────────────┘
     │
     ▼ (同出发地流程)
     │
     ▼
[收集出发日期]
     │
     ▼
[判断是否往返] ──是──► [收集返回日期] ──┐
     │                                  │
     ▼否                                │
[收集乘客信息] ◄────────────────────────┘
     │
     ▼
[收集舱位偏好]*
     │
     ▼
[参数确认展示]
     │
     ▼ 用户确认
[调用航班搜索API]
     │
     ▼
[展示搜索结果]
```

* 舱位偏好为可选，如用户未指定则默认所有舱位

## 6. 技术栈

- **LLM Provider**：待配置（OpenAI / Anthropic 等）
- **Agent Framework**：LangChain / LlamaIndex / 自定义 ReAct 循环
- **API Provider**：SerpAPI
- **API Key**：从 `.env` 的 `SERPAPI_KEY` 读取，禁止硬编码进代码或文档

## 7. 设计约束

1. **用户体验优先**：每一步操作都要有清晰的提示，避免用户困惑
2. **容错处理**：API 调用失败时提供友好的错误信息和重试机制
3. **数据验证**：用户输入的机场ID必须在 Autocomplete 返回的列表中
4. **上下文保持**：多轮对话中需记住用户已提供的信息，避免重复提问
